# 下一阶段升级思路（v1.3 规划）

> **状态：已归档。** 本文档规划的内容已在 v1.3 ~ v1.5 分期落地，v2.0 在此基础上补完
> 多模型投票、OpenAI 兼容适配层、数据页与配置自动迁移。实际变更见
> [`CHANGELOG.md`](../CHANGELOG.md)，保留本文仅作设计取舍的记录。

> 目标：**好看、好用、快、准**。
> 原则：不引入前端框架（保持零 CDN、离线可用、单文件打包），每一项改动都能单独回滚。

## 一、现状盘点（v1.2.3）

| 维度 | 现在是什么水平 | 短板 |
|---|---|---|
| 界面 | 4 标签页暗色控制台，41KB 原生 HTML | 信息平铺、没有「一眼看懂」的仪表盘；提示用裸文本，生硬 |
| 便捷 | 双击启动 → 浏览器 → 粘贴配置 | 题库只能粘贴文本；配置不能备份；手机看不了 |
| 速度 | 题库命中 1.3ms；模型答题 10~40s | 默认节律 500~1500ms 吃掉速度；云端每题重新 TLS 握手 |
| 准确 | 题库 + 订正 + 双模型验证 + 学科预设 | 外部题库只能精确命中；学科预设要手选；无相似题利用 |

## 二、更好看（用户第一诉求）

### 2.1 从「配置页」变成「仪表盘」

现在打开控制台，第一眼是一堆表单。应该先看到「今天答了多少、对了多少、省了多少钱」。

**顶部四张 KPI 卡**（数字滚动动效）：

| 卡片 | 内容 | 数据来源 |
|---|---|---|
| 今日答题 | 12 题 · 较昨日 +3 | `STATS` |
| 命中率 | 68%（题库 8 / 缓存 0 / 模型 4） | 新增统计 |
| 平均耗时 | 1.2s（P95 3.4s） | 新增 |
| 省下调用 | 8 次 · 约 ¥0.12 | `cost` 累计 |

### 2.2 实时答题流

右侧一列时间线，每题一条：

```
21:03:12  ● 题库命中   中国的首都是哪里？        1.3ms
21:03:20  ● 模型       简述 TCP 三次握手        2.4s
21:03:31  ● 低置信 ⚠   下列哪个不是…（建议核对）  4.1s
```

- 来源用颜色区分：题库=绿、缓存=蓝、模型=灰、订正=紫、失败=红
- 点一条展开：题干、选项、答案、模型、耗时、置信度
- 这是最能体现「系统在干活」的界面

### 2.3 首次使用向导

新用户第一次打开，弹三步引导（可跳过）：

1. 选模型（一键推荐：智谱免费 / 硅基流动 / 本地）
2. 贴 Key → 点「测试连接」（当场显示 ✅ 或具体错误）
3. 复制客户端配置（带「已复制」反馈）

目标：**从下载到出第一道答案 < 3 分钟**。

### 2.4 细节打磨

| 项 | 现在 | 改成 |
|---|---|---|
| 操作反馈 | 一行小字 | Toast（右下角浮出，3 秒消失，成功绿/失败红） |
| 加载 | 白屏等 | 骨架屏 + 按钮内 loading 转圈 |
| 空状态 | 「加载中…」 | 插画 + 一句引导（「还没有答题记录，去客户端发一道题试试」） |
| 危险操作 | `confirm()` 原生弹窗 | 自定义确认框，红色主按钮 |
| 主题 | 仅暗色 | 暗/亮切换，跟随系统 |
| 移动端 | 表格横向溢出 | 卡片式，底部 tab 栏 |
| 数字 | 静态 | 变化时滚动动画 |

**技术约束**：全部原生 CSS + 少量 JS，不引 Tailwind/Vue CDN（离线可用 + 打包体积）。图表用内联 SVG 手绘，约 80 行。

## 三、更便捷

| 功能 | 做法 | 价值 |
|---|---|---|
| **题库拖拽导入** | 把 .txt/.csv/.json 拖进页面即导入，自动识别格式 | 告别「复制几千行粘贴」 |
| **配置导出/导入** | 一个 `.jyconfig` 文件，含模型与参数（**不含 api_key**） | 换电脑 30 秒迁移 |
| **客户端配置一键下载** | 生成 `ocs_config.txt` 下载，不用手抄 JSON | 少一步出错 |
| **局域网二维码** | 后端生成 PNG（`qrcode` 库），手机扫码打开控制台 | 手机也能看状态 |
| **系统托盘**（可选依赖） | 最小化到托盘，右键「打开控制台/退出」 | 不用一直挂着黑窗 |
| **开机自启**（可选） | 写入启动项，一个开关 | 开机即用 |
| **快捷键** | `Ctrl+K` 命令面板（搜配置项/执行动作） | 高级用户提效 |

优先级：拖拽导入 > 配置导出 > 一键下载 > 二维码 > 托盘/自启。

## 四、更快

### 4.1 先搞清楚时间花在哪

| 环节 | 耗时 | 可否优化 |
|---|---|---|
| 题库/缓存命中 | 1.3ms | 已到极限 |
| **礼貌间隔（节律）** | **500~1500ms** | 可调，是最大的一块 |
| 云端 TLS 握手 | 80~200ms/题 | ✅ 连接复用可省 |
| 模型推理 | 1~30s | 换模型 / 降 token / 关 CoT |
| 本地模型加载 | 首题 5~20s | `keep_alive` 已有 |

### 4.2 四个动作

1. **连接复用**：`requests.Session` + `HTTPAdapter(pool_maxsize)`，云端每题省 80~200ms，本地省 5~10ms。改动小、收益确定。
2. **「快速模式」预设**：一键把间隔降到 100~300ms、关 CoT、`num_predict` 降到 512。给用户一个「我要快」的开关，而不是让他自己去改 6 个参数。
3. **缓存预热**：启动时把 `bank.json` 里 `hits` 最高的 200 题预载进内存缓存，第一题就命中。
4. **并发**：云端后端把 `max_concurrency` 默认提到 2（本地保持 1），排队时间减半。

**目标**：模型答题 P95 从 ~8s 降到 ~5s；命中 P95 < 5ms（关节律）。

## 五、更准确（核心）

### 5.1 相似题检索（RAG）—— 优先级最高

**问题**：现在只有「题干完全一致」才命中。24.9 万题导入后，大部分是死数据。

**方案**：
1. 建索引：题干做 2-gram，倒排 `gram -> [题目 id]`，构建 24.9 万题约 2~4 秒，内存 ~80MB
2. 查询：候选集做 Jaccard 粗排 → top-20 用 `difflib` 精排
3. 阈值：
   - `> 0.92`：直接返回题库答案（视为同题）
   - `0.75~0.92`：作为**参考**注入提示词（「同类题：…… 答案：C」），仍由模型判断
   - `< 0.75`：不干预
4. 只注入 top-2，避免提示词膨胀

**收益预估**：外部题库从「几乎无效」变成「每题多 2 条同考点参考」，正确率预计 +5~10 个百分点。
**风险**：错误参考会误导模型 → 必须用高阈值 + 只注入不覆盖 + 可一键关闭。

### 5.2 学科自动识别

现在 `prompt_preset` 要手选，实际没人会去切。
用关键词表 + 轻量打分（法条/病历/公式/代码特征），自动选预设，命中后打日志便于验证。成本半天，收益稳定。

### 5.3 多模型投票（3 选 2）

`verify_mode=full` 现在是「主 + 复核 + 仲裁」，本质是串行。改成并行三模型投票：
- 三个模型同时答，2 票以上为答案
- 只在「低置信 / 多选 / 计算题」触发，避免每题 3 倍成本
- 延迟由 `max` 决定，不比现在慢

### 5.4 题型识别修正

现存问题：编程题、填空题、判断题识别不准，路由到错误模型。
方案：扩充特征表（`#include`/`def `/`SELECT`/`____`/「下列…正确的是」），并允许「题型 → 模型」映射可视化配置。

### 5.5 答案自检

返回前做三道检查：
- 多选是否漏选（答案字母数 < 题干「多选题」提示）
- 字母是否越界（选项只有 A-D，却返回 E）
- 答案是否为空但 `success=true`

不合格 → 自动重答一次（换模型），仍不合格 → 标记低置信。

### 5.6 错题一键反馈

现在订正要手抄题干。改成：答题流里每题一个「👎 答错了」按钮 → 弹输入框填正确答案 → 自动带题干入库。**这是自建题库最快的积累方式**。

## 六、优先级与路线

| 优先级 | 内容 | 预估工作量 | 预期收益 |
|---|---|---|---|
| **P0** | KPI 仪表盘 + 实时答题流 + Toast | 2 天 | 观感质变，「好看」直接达成 |
| **P0** | 连接复用 + 快速模式预设 | 0.5 天 | 每题省 100~200ms |
| **P0** | 拖拽导入 + 客户端配置一键下载 | 1 天 | 使用门槛大幅下降 |
| **P1** | 相似题检索（RAG） | 2~3 天 | 正确率 +5~10 个点，外部题库真正可用 |
| **P1** | 学科自动识别 + 答案自检 | 1 天 | 正确率 +2~3 个点 |
| **P1** | 移动端适配 + 首次引导 | 1.5 天 | 手机可用 |
| **P2** | 配置导出/二维码/托盘/自启 | 2 天 | 便捷性 |
| **P2** | 多模型投票 | 2 天 | 难题正确率 +3~5 个点 |
| **P3** | 趋势图表、命令面板、主题切换 | 1.5 天 | 锦上添花 |

**建议节奏**：先做 P0 的 UI（用户最在意、见效最快），再做 RAG（真正提正确率），最后补便捷性。

## 八、不做的事（避免走偏）

- ❌ 引入 React/Vue 全家桶：破坏「单文件 + 离线」的立身之本
- ❌ 接入平台账号体系（登录态、Cookie）：合规风险
- ❌ 内置任何题库内容：体积和法律风险，题库永远外置
- ❌ 追求「全自动无人值守」：越自动，出错时越难排查

---

## 九、一句话总结

> **题库解决「重复题」，RAG 解决「同类题」，模型解决「新题」。三者各管一段，不要指望一个题库包打天下。**
> 界面上先让用户「看得见系统在干活」，比任何参数调优都更能体现价值。
