# 常见问题排查

按"从启动到答题"的顺序排列，遇到问题从上往下对照即可。

---

## 一、启动阶段

### 双击 `start.bat` / `OCS.exe` 一闪而过

控制台程序崩溃后窗口会立即关闭，看不到报错。用命令行跑一次就能看到原因：

```bat
cd /d 程序所在目录
OCS.exe --no-browser
```

或者：

```bat
python ocs_relay.py --no-browser
```

常见原因：缺 `flask` / `requests`（`pip install flask requests`）、端口被占、程序被放在无写权限目录（如 `C:\Program Files`）。

### 提示"端口被占用"

程序启动时会先检测端口，被占用会打印占用进程名。两种处理：

1. 控制台能打开的话：改端口 → 保存 → 重启（**OCS 里的 URL 要同步改**）
2. 命令行：`python ocs_relay.py --port 5001`

想知道谁占用了 5000：

```bat
netstat -ano | findstr :5000
tasklist | findstr <上面查到的PID>
```

### 浏览器没自动打开

程序其实已经起来了，手动访问 `http://127.0.0.1:5000/` 即可。
永久关闭自动打开：配置里 `auto_open_browser: false`，或启动加 `--no-browser`。

### 双击 `build.bat` 出现中文乱码

`build.bat` 已改为纯 ASCII 编码。若仍乱码，直接在 `cmd` 里执行：

```bat
python tools\build_exe.py
```

### 打包报错"找不到 build/_gen/ocs_relay.py"

说明没走构建脚本，直接对 `ocs_relay.spec` 跑了 PyInstaller。正确做法：

```bat
python tools\build_exe.py
```

这个脚本会先把 `console.html` 注入到 `build/_gen/ocs_relay.py`，再调 PyInstaller。

### exe 被杀毒软件报毒 / 被删

PyInstaller 单文件打包的通病（自解压行为类似加壳）。处理：加信任 / 白名单。
或者改用非单文件模式打包，或直接跑 `python ocs_relay.py`。

## 二、Ollama 相关

### 控制台显示"Ollama 服务：未连接"

依次试：

1. 控制台自检里点该项的「**修复**」按钮，程序会尝试拉起 Ollama 进程
2. 手动确认：任务栏右下角有没有小羊（羊驼）图标，没有就手动启动 Ollama
3. 命令行验证：

```bat
ollama list
```

4. 直接测接口：

```bash
curl http://127.0.0.1:11434/api/tags
```

有 JSON 返回说明 Ollama 正常，问题在端口配置（`ollama_url` 默认 `http://127.0.0.1:11434/api/generate`）。

### 自检提示"主模型未安装"

```bash
ollama pull qwen2.5:7b-instruct
```

或点自检里的「修复」，会新开窗口执行 pull。下载 4~5 GB，慢的话耐心等，或先换更小的模型：

```bash
ollama pull qwen2.5:3b
```

然后在控制台把主模型改成 `qwen2.5:3b`（注意要写全名，`ollama list` 里怎么显示就怎么填）。

### 备用模型显示 warn

`deepseek-r1:7b` 是**可选**的兜底，没装不影响使用（只是主模型失败时没有第二选择）。想装：

```bash
ollama pull deepseek-r1:7b
```

### Ollama 在别的机器 / 别的端口

改 `config.json` 的 `ollama_url`，例如 `http://192.168.1.10:11434/api/generate`。
注意 Ollama 默认只监听本机，跨机器需要在 Ollama 侧设置 `OLLAMA_HOST=0.0.0.0`。

## 三、答题阶段

### 每题都要等很久（20~60 秒）

7B 模型纯 CPU 推理就是这个速度，属正常。加速手段按性价比排序：

| 手段 | 效果 | 代价 |
|---|---|---|
| 换 `qwen2.5:3b` | 快 2~3 倍 | 准确率下降 |
| 开 GPU 加速（NVIDIA + CUDA） | 快 5~10 倍 | 需要显卡 |
| 提高 `keep_alive`（如 `1h`） | 省掉模型重载时间 | 占内存 |
| 减小 `num_ctx`（如 `2048`） | 略快 | 长题可能截断 |
| 减小 `num_predict`（如 `128`） | 略快 | 答案可能被截断 |

另外确认 `keep_alive` 没被设成 `0` —— 那样每次都重新加载模型，会慢几倍。

### 答题超时 / OCS 报错

OCS 单题上限 60 秒。程序内置 **50 秒硬预算**（`answer_budget`），到点必返回，会按剩余时间自动收缩每次重试的超时。

如果仍然超时：

- 确认 `answer_budget` < 58（自检会检查）
- 换小模型
- 看控制台日志里的 `cost` 字段，若单次推理就超过 40 秒，只能换模型 / 上 GPU

### 答案明显是乱猜 / 答非所问

这是**原理限制**，不是 bug。本地模型没有该题库的知识，冷门题只能靠推理猜。

改善方向（有限）：

- 换更大的模型（`qwen2.5:14b`、`qwen2.5:32b`），需要相应显存
- 确认 `temperature: 0.0`、`seed: 42` 没被改（保证同题同答案，便于复现）
- 题目文本残缺时，任何模型都无能为力

### 答案里带着"思考过程"/`<think>` 标签

程序有 8 步清洗流水线会自动剥离：完整/未闭合/大写/带属性/带空格的 `<think>`、中文「思考：」段、「答案：」前缀、括号解释、包裹引号、选项字母前缀。

如果还是漏出来了，把 `raw_answer` 字段（控制台"最近答题"或日志里能看到）发出来，方便定位是哪种形态没覆盖。

**根本解法**：不用 R1 系模型。`qwen2.5:7b-instruct` 不输出思考链，比 `deepseek-r1:7b` 快 3~5 倍，答案也更干净。

### 返回的是字母 `B` 而不是选项文字

理论上不该发生 —— 程序优先匹配选项正文。`match` 字段能看出来：

| match | 含义 |
|---|---|
| `exact` | 文本精确命中 ✅ |
| `fuzzy` | 相似度 ≥ 0.6 命中 ✅ |
| `letter` | 只能按字母下标回退 ⚠️ |
| `raw` | 完全没匹配上，原样返回 ❌ |

如果频繁出现 `letter` / `raw`，通常是 `options` 传的格式不对（比如整行是一坨没有换行）。确认 OCS 的 `data` 里是 `"options": "${options}"`，OCS 会自动用换行分隔选项。

### 多选题只答了一个

看 `type` 字段有没有传 `multiple`。程序对多选题会要求模型输出多个答案（多行 / `|` 分隔 / 字母组合都支持），最终答案会用换行连起来给 OCS。

判断题也一样，`type` 传 `judge` 时提示词会限定输出「正确/错误」。

### 每次都答题（缓存好像没生效）

缓存 key 是 `type + 题干(去空白) + 选项正文`。以下情况会 miss：

- 题干里有多余空格差异（程序会去掉所有空白后比对，一般不影响）
- 选项顺序变了
- `cache_size` 设得太小（默认 1024）
- 程序重启过（缓存是内存态）
- 同一个题干但 `type` 不同

缓存命中时 `cached: true`，控制台统计里"缓存"计数会加一。

### 同时来很多题会怎样

串行队列：同一时刻只跑一次推理，其余排队等（上限 `max_queue`，默认 32）。
超时或队列满了会返回 `{"success": false, "error": "队列已满或等待超时"}`，OCS 会把它当没答出来。

这是有意的设计 —— 本地模型并行推理会互相抢显存，反而全部变慢。

## 四、请求间隔与限流

### 节律延时是怎么算的

`wait = max(0, 目标间隔 - 已经花掉的时间)`，不是无脑 `sleep`。

| 情况 | 行为 |
|---|---|
| 推理本身已超过目标间隔 | 不再追加，直接返回 |
| 距上一题超过 `max_gap_ms`（6 秒） | 直接放行，不叠加 |
| 缓存命中 | 同样受间隔约束（保持节奏稳定） |
| 请求失败 | 同样受间隔约束（避免连续重试冲击上游） |

间隔分布右偏（`max(u1, u2)` 取两次均匀分布的最大值），小间隔少于大间隔，整体更平缓，避免突发流量。

### 调大 / 调小延时

`config.json`：

```json
"delay_min_ms": 500,
"delay_max_ms": 1500
```

或控制台"在线配置"里改，即时生效。总开关 `human_delay: false` 可整体关闭。

`responseType` 上限保护：`delay_max_ms` 不允许超过 15000。

### 只在本地加延时够吗

不够。**页面上的点击节奏要在 OCS 设置里调整**，建议答题间隔 5~8 秒。本地延时只控制"返回答案的时间"，管不到 OCS 何时点下一题。

## 五、配置与文件

### 改了配置没生效

除 `port` 外都即时生效。改端口必须重启程序，且 **OCS 的 `url` / `homepage` 要同步改端口**。

如果连非端口配置也不生效，检查是不是改错了文件 —— 配置写在**程序同目录**的 `config.json`：
- 源码运行：`ocs_relay.py` 同目录
- exe 运行：`OCS.exe` 同目录

### `config.json` 缺失 / 损坏

缺失没关系，程序首次运行会自动按默认值生成一份。

损坏的话，自检的"配置文件"项会显示 `fail` 并带修复按钮，点击会**先备份**为 `config.json.bak`，再用默认值重建。

也可以手动删掉，重启程序会重新生成。

### 配置里的 `_` 开头字段是什么

注释。程序读取时忽略，保存时原样保留。可以放心加自己的备注。

### 不想要 `config.json` 出现在仓库里

仓库的 `.gitignore` 已经忽略了它（以及 `relay.log`、`build/`、`dist/`）。
仓库里没有 `config.json` 也没关系，程序会自举。

### 日志文件在哪

程序同目录的 `relay.log`。滚动策略：单文件 2 MB，保留 3 个备份。

控制台的"运行日志"面板显示的是内存环形缓冲（最近 400 条），重启即清。

## 六、改界面

### 改了 `console.html` 没反应

浏览器缓存。`Ctrl + F5` 强制刷新。

还不行就确认文件位置：必须是**程序同目录**的 `console.html`（exe 运行时是 exe 同目录）。

### 改完怎么固化进 exe

```bash
python tools/build_exe.py
```

它会把 `console.html` base64 后注入 `build/_gen/ocs_relay.py` 的 `_CONSOLE_B64` 占位符，再打包。

源码里 `_CONSOLE_B64` 保持空字符串，所以 `ocs_relay.py` 本身始终是可读的（没有大段 base64）。

### 控制台显示"控制台页面缺失"

三级降级全都失败了：同目录没有 `console.html`、内嵌 base64 为空或损坏。**接口仍然完全可用**，可以直接 `POST /api/qa`。

处理：把 `console.html` 放回程序同目录，或者重新打包。

## 七、其他

### 能不能局域网/手机访问

```bash
python ocs_relay.py --host 0.0.0.0
```

然后别的设备访问 `http://<本机IP>:5000/`。

⚠️ 默认只监听 `127.0.0.1` 是有意的：这个服务没有任何鉴权，暴露到公网等于把本地模型和自检修复功能（能执行 `ollama pull`）对外开放。仅在可信内网使用。

### 会不会上传我的数据

不会。除了本机 Ollama（`127.0.0.1:11434`），程序不发起任何外部网络请求。控制台页面不引任何 CDN，全离线可用。

### 支持哪些系统

源码：Windows / Linux / macOS，Python 3.9+。
预编译 exe：Windows 64 位（PE32+）。

### 项目能商用吗

MIT 协议，可以。但因使用本软件产生的后果自行承担，详见 `LICENSE`。
